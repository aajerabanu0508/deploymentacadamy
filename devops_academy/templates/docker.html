Static Artifact Analogy: Executable Binary / Class Blueprint

Docker Image

An ordered, immutable collection of stacked root filesystem layers and execution metadata. An image is inert: it consumes no CPU, maintains no memory allocation, and has no process identifier (PID).

Mutability100% Read-Only (Immutable SHA-256 digest)
Resource FootprintDisk storage only (no CPU, RAM, or network interfaces)
Storage DriverOverlay2 lowerdir layers (read-only union mount)
$ docker build -t myapp:v1.0.0 .
Active Runtime Analogy: Running Process / Instantiated Object

Docker Container

A sandboxed, isolated Linux process running natively on the host kernel using namespaces (PID, NET, MNT, IPC, UTS) and cgroups for resource limits, with a thin read/write layer mounted on top.

MutabilityEphemeral Read/Write Layer (Copy-on-Write)
Resource FootprintActive CPU cycles, RAM heap, open socket descriptors
Storage DriverOverlay2 upperdir + merged view
$ docker run -d -p 5000:5000 myapp:v1.0.0
